Introduction

Getting started

JB
Joshua Birdman Created: May 06, 2023 - Updated: Apr 26, 2023

Set up the library, create your first cache, and learn where to ask for help when you get stuck.

Quick start

Start with an existing project or create an empty folder to try the examples. Open the project directory in your editor and keep a terminal open next to it.

Installing dependencies

If your project uses Tailwind CSS 3, you can add the forms and typography plugins. Install them with your package manager, then add them to the plugins array in your Tailwind configuration.

plugins: [
    require('@tailwindcss/forms'),
    require('@tailwindcss/typography'),
]

Restart the development server after editing the configuration. Open a page with a form or an article to check that the plugin styles are loaded.

Configuring the library

Keep the configuration file in the root of the project so everyone on the team can find it. Start with the default settings and change one option at a time. That makes it easier to tell which change caused an unexpected result.

Use the same settings when testing locally as you do when building the project. If a setting differs between environments, document where it comes from and provide a working default for local development.

Basic usage

Use the cache for data you read often, such as a list of team members. Give each result a key so you can find the same data again on the next request.

Your first cache

Try reading the members list twice. The first read loads the data and stores it under a key. The second read can use the stored value until it expires or the members list changes.

Change your password

  1. Open the team menu.
  2. Select your profile.
  3. Go to account settings.
  4. Expand the password section.
  5. Fill in the current and new password fields.
  6. Save the change.

Use a small set of sample records when checking the layout. This table shows the fields displayed on the members page.

Adding middleware

Register middleware before the handlers that need it. For example, a request logger can run before each handler so it records successful requests and errors. Check the order by sending a request and looking at the development log.

If a handler updates a record, clear the matching cache entry after the update succeeds. The next read will load the current value.

Getting help

Check the guides first to see whether an example covers your case. If you still need help, describe what you tried and include the error you saw.

Submit an issue

Include the library version, the steps to reproduce the problem, and the result you expected. A short example makes it easier for someone else to reproduce the issue.

Join the community

Ask questions, share what you are building, or help someone work through an example. If you find a confusing step in the documentation, point to the heading so others can find it quickly.
